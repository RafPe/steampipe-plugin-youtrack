# YouTrack REST API pushdown matrix

This matrix records only equivalences documented by the JetBrains YouTrack REST API. It is a design boundary for SQL qualifier pushdown: predicates not listed as safe stay local, even when a similarly named response field exists.

## Common request rules

- Collection endpoints document `fields`, `$top`, and `$skip`. The plugin may use these for explicit projections and pagination; SQL limits can safely reduce `$top`. A missing `$top` is not an unlimited request: YouTrack applies a server-side collection limit, commonly 42, while `/api/issues` is additionally governed by the instance's **Max issues to export** setting. See [query syntax and pagination](https://www.jetbrains.com/help/youtrack/devportal/api-query-syntax.html) and [issues](https://www.jetbrains.com/help/youtrack/devportal/resource-api-issues.html).
- A single-resource identifier is pushed only where the corresponding operation explicitly documents that identifier form. Database IDs are opaque strings. Human-readable issue IDs, article IDs, project short names, and user logins are not interchangeable unless the operation says so.
- Visibility and permissions are evaluated by YouTrack. A successful list is therefore the set visible to the token, not necessarily every object in the installation. Nested resources also inherit access constraints from their parent issue or project.
- `fields` changes representation, not row selection. Response columns and arbitrary SQL predicates must not be converted into undocumented query parameters.

## Pushdown invariants

1. Prefer a documented single-resource or parent-scoped route over scanning a collection and filtering locally.
2. Prefer `/api/admin/projects/{projectID}/issues` for an exact project qualifier; it preserves the caller's identifier and avoids changing semantics through generated YouTrack search text.
3. Preserve repeated `author`, `creator`, and `customFields` parameters as repeated URL values, not comma-joined strings.
4. Convert SQL timestamps to Unix milliseconds only for parameters documented as `Long`; preserve `YYYY-MM-DD` only for `startDate` and `endDate`.
5. Never push partial matches, case folding, ranges, `IN`, or null tests unless a documented endpoint parameter has the same semantics. The remaining predicate must be evaluated by Steampipe.
